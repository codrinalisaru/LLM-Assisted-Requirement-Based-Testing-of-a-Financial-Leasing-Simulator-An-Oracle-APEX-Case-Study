
<h1>LLM-Assisted Requirement-Based Testing of a Financial Leasing Simulator: An Oracle APEX Case Study</h1>

<p>
This repository contains the experimental artifacts and replication package supporting the paper
<strong>"LLM-Assisted Requirement-Based Testing of a Financial Leasing Simulator: An Oracle APEX Case Study."</strong>
</p>

<p>
The Oracle APEX application used as the System Under Test (SUT) is available at:
<a href="https://oracleapex.com/ords/r/workspace_01/simulators189448/home">
Oracle APEX Leasing Simulator
</a>
</p>

<p>The study evaluates three Large Language Models (ChatGPT, Gemini, and Claude) in two testing activities:</p>

<ol>
<li>
<strong>Requirement-based test-case generation:</strong>
Evaluation of LLM-generated test suites in terms of requirement coverage, test-case validity, execution outcomes, and defect detection, including comparison with a conventional reference baseline.
</li>
<li>
<strong>LLM-assisted test oracle generation:</strong>
Evaluation of LLM-generated expected leasing payment schedules against deterministic reference calculations and actual Oracle APEX outputs across three financial scenarios and three independent runs per model.
</li>
</ol>

<h2>Repository Contents</h2>

<h3>1. Results_Leasing.xlsx</h3>

<p>
Main experimental workbook containing the data used for test generation, requirement coverage, test execution, defect analysis, conventional baseline comparison, and LLM-assisted test oracle evaluation.
</p>

<p>The workbook contains the following worksheets:</p>

<h4>Reqs</h4>
<p>
Structured requirement specification used in the experiment, including functional requirements, computational rules, business rules, input constraints, and process requirements. Requirement identifiers are used throughout the test-case evaluation and traceability analyses.
</p>

<h4>TCs baseline</h4>
<p>
Conventional reference test suite containing manually designed test cases derived from the leasing simulator requirements. The worksheet includes positive, negative, and boundary-value scenarios, expected outcomes, requirement identifiers, observed Oracle APEX results, and Pass/Fail assessments.
</p>
<p>
This baseline provides a non-LLM reference for comparing the evaluated test suites.
</p>

<h4>Models</h4>
<p>
Information about the LLMs and model versions used in the study, including model identification and experimental configuration details.
</p>

<h4>TCs eval</h4>
<p>
Consolidated quantitative evaluation of the LLM-generated test suites, including test-case distribution, requirement coverage, and test execution results. The worksheet supports comparisons between the evaluated models and test-case categories.
</p>

<h4>Defects</h4>
<p>
Consolidated record of failed test cases and observed defects or discrepancies identified during test execution. The worksheet brings together evidence from the conventional reference baseline and the LLM-generated test suites, supporting analysis of defect detection and overlapping findings.
</p>

<h4>Reqs vs TCs</h4>
<p>
Requirement-to-test traceability matrix linking individual requirement identifiers to the test cases generated by ChatGPT, Gemini, and Claude. The worksheet provides the underlying evidence for explicit requirement coverage calculations and identifies requirements exercised by the generated test suites.
</p>

<h4>TCs ChatGPT</h4>
<p>
Test cases generated by ChatGPT, including preconditions, input data, test steps, expected results, observed Oracle APEX outputs, and Pass/Fail execution assessments.
</p>

<h4>TCs Gemini</h4>
<p>
Test cases generated by Gemini, including test scenarios, execution instructions, expected outcomes, actual Oracle APEX outputs, and Pass/Fail assessments.
</p>

<h4>TCs Claude</h4>
<p>
Test cases generated by Claude, including test scenarios, preconditions, input data, execution steps, expected results, observed outputs, and Pass/Fail assessments.
</p>

<h4>Oracle cases</h4>
<p>Input configurations for the three oracle-assistance scenarios:</p>
<ol>
<li>Standard non-zero interest schedule.</li>
<li>Zero-interest schedule.</li>
<li>Rounding-sensitive final-adjustment schedule.</li>
</ol>
<p>
These configurations were used consistently across the evaluated models and experimental runs.
</p>

<h4>Oracle results - run1</h4>
<p>
Detailed row-by-row and column-by-column comparison of Oracle APEX outputs, deterministic human reference schedules, and LLM-generated expected schedules obtained during the first experimental run.
</p>

<h4>Oracle results - run2</h4>
<p>
Detailed comparison of the same three leasing scenarios using the expected schedules generated during the second independent experimental run.
</p>

<h4>Oracle results - run3</h4>
<p>
Detailed comparison of the same three leasing scenarios using the expected schedules generated during the third independent experimental run.
</p>

<p>
Together, the three worksheets support the evaluation of numerical correctness, exact matching, discrepancies, and repeatability across model executions.
</p>

<h4>Oracle-Synthesis</h4>
<p>
Consolidated summary of the oracle-assistance experiment, reporting the number of successful exact-match results for each model and scenario across the three experimental runs. The worksheet provides an overall comparison of oracle-generation correctness and repeatability.
</p>

<h4>Human eval</h4>
<p>
Deterministic reference payment schedules calculated independently using spreadsheet formulas. The worksheet contains the reference computations used to validate the actual Oracle APEX schedules and the candidate expected outputs generated by the LLMs, including interest calculations, principal amortization, periodic rounding, and final-installment adjustments.
</p>

<h3>2. Leasing prompt.docx</h3>

<p>
Contains the complete prompts and requirement information supplied to the LLMs during the experiments.
</p>

<p>The document includes:</p>
<ul>
<li>The structured requirement specification used for requirement-based test-case generation.</li>
<li>Instructions for generating positive, negative, and boundary-value test cases.</li>
<li>The oracle-assistance prompt defining leasing computational rules, payment-date rules, rounding behavior, output structure, and formatting constraints.</li>
<li>Input data for the three oracle-assistance scenarios.</li>
</ul>

<h3>3. Chatgpt as oracle_run1.docx, Chatgpt as oracle_run2.docx, Chatgpt as oracle_run3.docx</h3>

<p>
Contain the ChatGPT responses obtained during the three independent oracle-assistance runs.
</p>
<p>
Each document preserves the prompts and generated outputs for the three evaluated scenarios, including intermediate calculations and candidate expected payment schedules.
</p>
<p>
These outputs were subsequently compared against the deterministic reference schedules and Oracle APEX outputs.
</p>

<h3>4. Claude as oracle_run1.docx, Claude as oracle_run2.docx, Claude as oracle_run3.docx</h3>

<p>
Contain the complete Claude responses obtained during the three independent oracle-assistance runs.
</p>
<p>
Each document preserves the prompts, intermediate calculations, and candidate expected payment schedules for all three leasing scenarios.
</p>
<p>
The outputs were evaluated against the independently calculated deterministic references and actual Oracle APEX results.
</p>

<h3>5. Gemini as oracle_run1.docx, Gemini as oracle_run2.docx, Gemini as oracle_run3.docx</h3>

<p>
Contain the complete Gemini responses obtained during the three independent oracle-assistance runs.
</p>
<p>
Each document includes the prompts, intermediate calculations, and candidate expected payment schedules for the three leasing scenarios.
</p>
<p>
The generated outputs were used in the row-by-row and column-by-column comparisons reported in the study.
</p>

<h3>6. Oracle_case1_standard.xlsx</h3>

<p>
Exported payment schedule produced by the Oracle APEX leasing simulator for Case 1: Standard non-zero interest schedule.
</p>
<p>
The scenario represents the normal computational path of the leasing simulator, using a non-zero annual interest rate. The workbook contains the observed SUT output used for comparison with the deterministic reference and LLM-generated candidate schedules.
</p>

<h3>7. Oracle_case2_zero interest case.xlsx</h3>

<p>
Exported payment schedule produced by the Oracle APEX leasing simulator for Case 2: Zero-interest schedule.
</p>
<p>
This scenario exercises the dedicated zero-interest computational rule, where the regular payment is calculated without the standard annuity formula. The workbook contains the actual Oracle APEX output used in the oracle-assistance evaluation.
</p>

<h3>8. Oracle_case3_rounding sensitive final adjustment.xlsx</h3>

<p>
Exported payment schedule produced by the Oracle APEX leasing simulator for Case 3: Rounding-sensitive final-adjustment schedule.
</p>
<p>
This scenario evaluates numerical sensitivity to periodic rounding and the final-installment adjustment required for the outstanding balance to converge exactly to the residual value.
</p>
<p>
The workbook contains the observed Oracle APEX schedule used for comparison with the deterministic reference and LLM-generated outputs.
</p>

<h3>9. Workflow diagram.drawio.pdf</h3>

<p>
Diagram illustrating the experimental workflow used in the study.
</p>

<p>The diagram presents two complementary processes:</p>

<ul>
<li>
<strong>Test-generation workflow:</strong>
Requirements, prompt construction, LLM test-case generation, manual review, requirement traceability, Oracle APEX execution, and Pass/Fail and defect analysis.
</li>
<li>
<strong>Oracle-assistance workflow:</strong>
Predefined leasing scenarios, LLM oracle generation, comparison against deterministic references and actual Oracle APEX outputs, exact-match evaluation, and repeatability assessment across three runs.
</li>
</ul>

<h2>Replication and Evaluation Notes</h2>

<p>
The experimental artifacts are organized to support inspection and replication of the study's evaluation procedures.
</p>

<p>
For requirement-based testing, the <strong>Reqs</strong> worksheet defines the requirements, while <strong>TCs baseline</strong>, <strong>TCs ChatGPT</strong>, <strong>TCs Gemini</strong>, and <strong>TCs Claude</strong> contain the evaluated test cases and execution results. The <strong>Reqs vs TCs</strong>, <strong>TCs eval</strong>, and <strong>Defects</strong> worksheets provide the supporting traceability, quantitative evaluation, and defect evidence.
</p>

<p>
For oracle-assisted testing, the <strong>Oracle cases</strong> worksheet defines the experimental inputs, and <strong>Human eval</strong> contains the independently calculated deterministic reference schedules.
</p>

<p>
The three <strong>Oracle results - run1</strong>, <strong>Oracle results - run2</strong>, and <strong>Oracle results - run3</strong> worksheets document comparisons for each experimental run, while <strong>Oracle-Synthesis</strong> consolidates the exact-match results.
</p>

<p>
The original LLM responses and Oracle APEX schedule exports are provided separately to facilitate verification of the reported findings.
</p>

<p>
All experimental results should be interpreted within the scope of the evaluated models, prompts, leasing scenarios, and Oracle APEX application configuration.
</p>
